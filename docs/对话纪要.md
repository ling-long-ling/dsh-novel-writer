## 三、最终做成的东西

**插件形态**：`dsh-novel-companion` v1.0.0，一个 DSH Desktop 插件（Host 半 + Client 半），中文名「小说创作搭档」。

| 维度 | 设计 |
| --- | --- |
| 两个入口 | 左侧边栏**「小说」面板**（人改）+ 对话里的 **`novel` 工具**（模型读写），共用同一份数据 |
| 创作流程 | 7 阶段：了解作者 → 世界观 → 人物 → 情节 → 分章大纲 → 写正文 → 收尾 |
| 设定板块 | 6 个：`core` 内核、`world` 世界观、`characters` 人物、`plot` 情节、`rules` 设定规则、`style` 文风；每块 `draft/final` + 待问问题清单 |
| 章节 | 三态 `outline → writing → final`，大纲必须先由作者修改定稿才写正文 |
| 数据 | DSH 存储域 `novel_companion` → 表 `projects`（single JSON，`%DSH_HOME%\storages\novel_companion.json`） |
| Agent 侧 | `novel` 工具 8 个 action（list/get/create/stage/block/outline/chapter/appendChapter）+ 一段系统提示词摘要，模型始终知道项目进度 |
| 规模 | 37 个文件 / 约 41.6 万字节；Host 半 679 行、Client 生成后 1566 行、共享逻辑 394 行、14 个自检脚本 |
| 质量保障 | `node scripts/verify.mjs` 一条命令 16 项检查：真实 Cordis Context 挂载、服务商规则校验 schema、极简 React 真实渲染面板、全链路模拟等 |

## 六、DSH 插件框架踩坑清单（继续开发必读）

| 坑 | 现象 | 正确做法 |
| --- | --- | --- |
| `ctx.Service` | 读取它会让整个 Host 退出，不是只停插件 | 用 `ctx.provide(ns, instance)` 发布服务 |
| Remote 描述符 | 方法不可见 / 所有按钮失效 | 键是**字符串** `@deepseek-ai/dsh-typert-protocol/remote-methods`，定义在类**原型**上 |
| `ctx.tools.register` 的 `parameters` | 服务商 400，整轮对话死 | 必须编译成正规 JSON Schema（对象根 + `required` 数组），不能传参数表 |
| `ctx.remote.<ns>` | 第三方命名空间是 `undefined` | 用 `ctx.connection.rpc.call('/api', '<ns>/<method>', { args })` |
| `main` 槽位 | 没有 `sessionId` prop | 主会话 id 取 `ctx.get('uiSession').adapter.current`，或回退 props |
| 面板被皮肤遮挡 | 渲染正常但完全看不见 | 根节点 `position:relative; z-index:1; isolation:isolate` |
| 主题 token | 只有 14 个真实 token | 只用真实 token；别把背景 token 当文字色（皮肤会把它设成透明） |
| Host 半更新 | 改了代码运行时仍是旧行为 | Host 半**不热重载**，必须完全重启 DSH Desktop；Client 半刷新即可 |
| linked 包依赖 | `schemastery` / 部分 `@deepseek-ai/*` 解析失败 | 只能 import `node:*`、自身相对文件、`@deepseek-ai/*` 内置包 |
| profile 手改 | BOM 导致 HMR `SyntaxError: Unexpected token '锘'` | 不要手改出 BOM；优先用 DSH 插件管理器安装 |

## 七、结尾「压缩」为什么没成功（重要）

- 第 18 轮开始前，模型从 `deepseek-flash`（1M 窗口）**切回了 `a1/deepseek-v4.1-flash`（262,144 窗口）**。
- 此时那条对话的上下文压力约 **343,433 tokens**，已经超过 262k 窗口。
- 因此第 18、19 轮每次唤醒都会触发自动压缩，但**生成摘要的请求本身也带着超窗历史**：
  - 6 次 `compaction/start → end` 全部带错误 `pi-ai detected context overflow for model "deepseek-v4.1-flash"`；
  - turn 18、turn 19 均以 `CONTEXT_WINDOW_EXCEEDED` 结束。
- 结论：**在那条对话里点「压缩」/ 输入 `/compact` 也会失败**（同一后端、同一超窗摘要请求），不是按钮坏了。
- 解法（任选其一）：
  1. 打开那条对话 → 把模型切回 **`deepseek-flash`（1M 窗口）** → 先正常发一句话（让一次请求成功、确认路由）→ 再执行 `/压缩`；
  2. 直接用新对话继续（这份纪要 + 代码包就是为此准备的）。
- 提醒：这是 **模型窗口配置问题，不是插件代码问题**；插件代码在 19:39 已定稿。
